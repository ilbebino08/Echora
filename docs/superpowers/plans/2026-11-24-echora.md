# Echora Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** App Android che ascolta di continuo dal microfono tramite un processo privilegiato (Shizuku/Sui, sorgente `HOTWORD`) e tiene gli ultimi N minuti in un buffer circolare che l'utente salva in WAV quando vuole.

**Architecture:** Due ruoli nello stesso APK. Il processo privilegiato (`Shizuku.UserService`, uid 0 con Sui o 2000 con Shizuku via ADB) possiede solo l'`AudioRecord` e lo espone via AIDL. Il processo app (`CaptureService` foreground) legge i campioni via Binder, li scrive in un file circolare preallocato, e al salvataggio estrae gli ultimi N minuti in un WAV. Durante una chiamata il processo privilegiato cambia sorgente (VOICE_CALL, oppure REMOTE_SUBMIX+MIC).

**Tech Stack:** Kotlin, Jetpack Compose, Shizuku API 13.1.5 + provider 13.1.5 + Refine 4.4.0, AIDL, FileChannel, MediaStore.

**Spec:** `docs/superpowers/specs/2026-11-24-echora-design.md`

## Global Constraints

- Package `com.echora.app`, `minSdk 31`, `compileSdk`/`targetSdk` 36 (alzare a 37 solo se il toolchain regge).
- Nessun permesso `RECORD_AUDIO` nel manifest, mai.
- Formato buffer unico: PCM 16 bit, mono, 16000 Hz → 32000 byte/s, 1,92 MB/min.
- Buffer default 10 minuti, modificabile 1–60, capienza = `minuti * 60 * 32000` byte, file preallocato.
- Uscita: WAV PCM16 mono 16 kHz, in `MediaStore` sotto `Music/Echora/`.
- Foreground service type `specialUse` (mai `microphone`).
- UI in italiano.
- Codice scritto da zero: non copiare file da AmbientMusicMod (GPL-3.0). Il documento `docs/accesso-microfono-privilegiato.md` è la descrizione del pattern.
- Device di riferimento: Samsung SM-S916B, Android 17 (API 37), root KernelSU, `adb shell` già uid 0, Shizuku installato e attivo come uid 0.

## Review Focus

1. **Avvolgimento del buffer**: un WAV salvato quando il buffer ha già girato deve contenere l'ordine giusto (vecchio→nuovo) e nessun byte di spazzatura. Test in Task 3/4.
2. **Cattura muta**: se `read()` restituisce ≤ 0 o un blocco di zeri, la UI non deve dire "in registrazione" con un buffer di silenzio. Test in Task 8.
3. **Spazio su disco**: se il file circolare non si può allocare (spazio insufficiente) l'app deve degradare con un messaggio, non crashare. Test in Task 3/10.
4. **Cambio sorgente durante chiamata**: il passaggio HOTWORD→VOICE_CALL/REMOTE_SUBMIX non deve corrompere il buffer né lasciare aperta la sorgente di chiamata a chiamata finita. Verifica device Task 9.
5. **Riavvio**: con l'interruttore spento il servizio non deve partire al boot; con Shizuku via ADB non deve crashare ma mostrare "non disponibile". Verifica device Task 8.

### Task 3: Buffer circolare su file (TDD)

**Files:**
- Create: `app/src/main/java/com/echora/app/audio/PcmRingBuffer.kt`
- Test: `app/src/test/java/com/echora/app/audio/PcmRingBufferTest.kt`

**Interfaces:**
- Consumes: niente.
- Produces:
  - `class PcmRingBuffer(file: File, capacityBytes: Int)` con `fun reset()`, `fun append(src: ByteArray, offset: Int = 0, count: Int = src.size)`, `fun filledBytes(): Long`, `fun readLast(byteCount: Long): ByteArray`, `fun close()`.
  - `readLast` restituisce al massimo `min(byteCount, filledBytes())` byte, in ordine dal più vecchio al più nuovo.

- [ ] **Step 1: Scrivi i test che falliscono**

```kotlin
// PcmRingBufferTest.kt
private fun buf(cap: Int) = PcmRingBuffer(File.createTempFile("ring", ".pcm"), cap)

@Test fun `readLast returns appended bytes in order`() {
    val b = buf(100)
    b.append(ByteArray(10) { it.toByte() })
    assertArrayEquals(ByteArray(10) { it.toByte() }, b.readLast(1000))
}

@Test fun `readLast returns only the newest bytes after wraparound`() {
    val b = buf(10)
    b.append(ByteArray(15) { it.toByte() })          // 0..14, capienza 10
    assertArrayEquals(ByteArray(10) { (it + 5).toByte() }, b.readLast(10))
}

@Test fun `filledBytes saturates at capacity`() {
    val b = buf(10); b.append(ByteArray(25))
    assertEquals(10L, b.filledBytes())
}

@Test fun `reset empties the buffer`() {
    val b = buf(10); b.append(ByteArray(10)); b.reset()
    assertEquals(0L, b.filledBytes()); assertEquals(0, b.readLast(10).size)
}

@Test fun `capacity file is preallocated and rejects impossible size`() {
    val f = File.createTempFile("ring", ".pcm")
    PcmRingBuffer(f, 10).close()
    assertEquals(10L, f.length())
}

@Test fun `unallocatable capacity throws instead of silently truncating`() {
    val f = File.createTempFile("ring", ".pcm")
    assertThrows(IOException::class.java) { PcmRingBuffer(f, Int.MAX_VALUE) }
}
```

- [ ] **Step 3: Implementa `PcmRingBuffer`**

`RandomAccessFile(file, "rw")`, `setLength(capacityBytes.toLong())` nel costruttore; `writeOffset: Int`, `filled: Int`. `append` scrive a `writeOffset` e, se sfora, scrive la coda all'inizio del file; `filled = min(capacity, filled + count)`. `readLast` parte da `(writeOffset - n + capacity) % capacity` e legge in uno o due `readFully`. Se `start() < capacity` e `filled == capacity` legga tutta la coda; `reset` azzera i contatori, `close` chiude il file.

- [ ] **Step 3: Implementa il loop di cattura**

`ShellConnection.start()` → attesa `READY` (timeout 10 s → `Error`) → `capture.open(1999, 16000, 1, 128000)` → `PcmRingBuffer(File(filesDir, "buffer.pcm"), settings.bufferMinutes * 60 * 32000)` con `reset()` → `capture.setMicListener { disabled -> stato MicDisabled / ripresa }` → loop: `val n = capture.read(chunk, chunk.size)`; `n > 0` → `ring.append(chunk, 0, n)`; `n == 0` → continua; `n < 0` → `Error`, teardown, retry con backoff; ogni 5 s aggiorna `CaptureStates`. Se `filledBytes` cresce e i campioni sono tutti zero per 10 s consecutivi → `Error("nessun audio dal microfono")`. Se `!CaptureService.isAlive` → rilascia record e chiude il buffer in `onDestroy`.
